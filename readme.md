запуск: 
    приложение:
        . : `docker compose up`
    тесты (только для сервиса аутентификации):
        /services/accounts : `docker compose -f compose.test.yaml up`

Для удобства проверки и обеспечения запуска проекта «из коробки» (docker-compose up),
переменные окружения и пароли к базе данных намеренно оставлены в файлах docker-compose.yaml

В приложении реализована Role-Based Access Control структура управления ограничениями доступа:

| method | endpoint | description | not auth | user | admin |
|:---|:---:|:---|:---:|:---:|:---:|
| `POST` | `/auth/accounts` | регистрация пользователя. | ✅ | ✅ | ✅ |
| `DELETE` | `/auth/accounts` | удаление аккаунта(мягкое). | ❌ | ✅ | ✅ |
| `PATCH` | `/auth/accounts` | изменение пароля пользователя. | ❌ | ✅ | ✅ |
| `POST` | `/auth/tokens` | получения access, refresh токенов. | ✅ | ✅ | ✅ |
| `POST`| `/auth/refresh` | получение access токена по refresh токену. | ❌ | ✅ | ✅ |
| `POST` | `/resource/users` | создание профиля пользователя с именем которое отображается при публикации поста. | ❌ | ✅ | ✅ |
| `POST` | `/resource/posts` | публикация поста. | ❌ | ✅ | ✅ |
| `GET` | `/resource/posts` | чтение постов с пагинацией. | ✅ | ✅ | ✅ |
| `GET` | `/resource/secrets` | демонстрационный вариант применения прав администратора. возвращает строку 'secret' если роль admin. | ❌ | ❌ | ✅ |

Для упрощёной проверки API можно использовать Swagger:

http://127.0.0.1/auth/docs - сервис аутентификации. выдаёт токены регистрирует пользователей. (покрыт тестами)
http://127.0.0.1/resource/docs - главный сервис который предоставляет возможность публиковать посты и читать их

В микросервисе аутентификации (http://127.0.0.1/auth/) зарегистрированы 2 пользователя : 
1.  email = user@example.com
    password = string
    роль = user (обычный пользователь)

2.  email = admin@example.com
    password = admin
    роль admin (администратор)

Для взаимодействия необходимо получить access токен по  `POST` `/auth/tokens`
Для публикации постов необходимо создать профиль в сервисе resource `POST` `/resource/users` после аутентификации (полчения access токена)
